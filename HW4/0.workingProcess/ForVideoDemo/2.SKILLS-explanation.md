Bản chất của file `SKILLS.md` đóng vai trò là một **bộ quy tắc cốt lõi (System Prompt / Custom Instructions)** để định hình hành vi của AI. Thay vì để AI tự do sinh ra một đống code không kiểm soát, file này ép AI phải làm việc như một trợ lý tuân thủ kỷ luật, giải quyết triệt để các yêu cầu khắt khe của HW04.

Dưới đây là giải thích chi tiết về quy trình, cơ chế hoạt động và những điểm bạn cần đặc biệt lưu tâm để đạt điểm tối đa.

### 1. Quy trình hoạt động của SKILLS.md (4 Bước Chặn)

File này thiết lập một **Standard Operating Procedures (SOP)** gồm 4 bước nối tiếp nhau. Ở cuối mỗi bước, AI bị ép buộc phải "dừng lại và hỏi ý kiến bạn" thay vì tự ý làm tiếp.

* **Bước 1: Thiết kế Test & Dữ liệu (Test Design & Data):** AI phân tích FR (như FR-19, FR-05) và sinh ra đúng 12 test cases kèm file dữ liệu `.json` hoặc `.csv`. *Nó sẽ dừng lại chờ bạn chốt dữ liệu.*
* **Bước 2: Sinh mã kiểm thử (Script Generation):** Sau khi bạn "OK", AI mới viết code Playwright. Nó bị ép phải comment rõ vị trí của 3 assertion patterns. *Nó sẽ dừng lại chờ bạn mang code đi chạy thử.*
* **Bước 3: Báo cáo lỗi (Bug Reporting):** Nếu trong lúc chạy thử, script phát hiện ra SUT bị lỗi (ví dụ lỗi HTTP 200 False Success ở FR-19), AI sẽ tự động đọc file `bug-report.md` trong thư mục `references` để điền sẵn một báo cáo lỗi chuẩn chỉnh cho bạn.
* **Bước 4: Nhật ký kiểm toán AI (AI Audit Logging):** Để giúp bạn làm file `AI Audit Report_Vn.docx.md` nộp cho giáo viên, AI sẽ tự động tóm tắt lại phiên làm việc (Ngày giờ, Prompt của bạn, Nội dung AI đã làm) để bạn copy-paste nhanh chóng.

### 2. AI sử dụng file này như thế nào?

Khi bạn nạp `SKILLS.md` vào các công cụ như Cursor hoặc VS Code Copilot, AI sẽ đối chiếu mọi yêu cầu của bạn với bộ luật trong file:

* **Giới hạn bối cảnh:** Nếu bạn bảo "Automate FR-19 đi", AI đọc `SKILLS.md` sẽ hiểu ngay FR-19 là gì, database cấu trúc ra sao, và biết luôn là có lỗi tự xóa Admin ở đó để viết test case cố tình "bắt" lỗi này.
* **Chống sinh code rác (Hardcode):** AI bị cấm tiệt việc nhét mảng dữ liệu thẳng vào file code `.spec.ts`. Nó bắt buộc phải dùng lệnh đọc file ngoài (Data-driven testing).
* **Chống vi phạm "Single Generic Prompt":** Giáo viên cấm việc dùng một prompt chung chung để sinh toàn bộ bài làm. Việc AI tự động chia nhỏ thành 4 bước chính là bằng chứng thép cho thấy bạn đã "điều hướng AI từng bước" (Drive AI step-by-step).

### 3. Những điểm bạn CẦN LƯU Ý (Góc độ thẩm định viên)

Dù AI đã có "vòng kim cô", bạn vẫn là người kiểm duyệt cuối cùng. Hãy mang tư duy hoài nghi và chuyên sâu vào các điểm sau:

* **Giám sát chặt "Human Review" & "AI Critique":** Đây là phần ăn điểm nặng nhất. Cố tình để ý xem ở Bước 2, AI có dùng các bộ chọn (selectors) quá mong manh không (ví dụ dùng XPath quá dài thay vì `getByRole`). Nếu phát hiện, hãy tự tay sửa lại mã, và ghi ngay lỗi này của AI vào mục **AI Critique (200-300 từ)** trong báo cáo chính.
* **Xác minh Metadata Report:** Mặc dù file skill đã dặn AI cấu hình report HTML, bạn phải tự tay kiểm tra lại file `playwright.config.ts` để chắc chắn dòng chữ *"Run by: 23120242"* đã được chèn thành công vào cấu hình hiển thị của Allure hoặc Playwright Report.
* **Xử lý Flaky Tests (Test chập chờn):** EShop là một hệ thống có độ trễ thực tế. AI đôi khi sẽ viết code click quá nhanh trước khi giao diện kịp load (đặc biệt ở luồng thanh toán FR-11). Bạn phải chủ động thêm các hàm `waitForResponse` hoặc kiểm tra tính khả dụng (visibility) thay vì phụ thuộc hoàn toàn vào code AI sinh ra.
* **Đường dẫn thư mục references:** Đảm bảo bạn đặt thư mục `references` (chứa các file template markdown của giáo viên) cùng cấp với file `SKILLS.md` để AI trong Cursor có thể đọc và trích xuất đúng biểu mẫu khi gen Bug Report hoặc Test Summary.
