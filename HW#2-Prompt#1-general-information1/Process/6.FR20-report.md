# FR-20 Report - Mobile Product Browsing and Order History

## Step B - Boundary Value Analysis

### Scope and prerequisite

- Feature scope: mobile product browsing/search and authenticated mobile order
  history.
- Out of scope: mobile authentication, profile editing, cart, checkout, and
  order cancellation.
- Step A Gate A was approved on 2026-10-18 with no corrections.
- This report records the FR-20 BVA and Step C test-case design.

### Boundary analysis

FR-20 reuses the approved product-search boundaries from FR-05 and the
order-history cardinality boundaries from FR-11:

- Mobile search length: `0` characters versus `1+` characters; maximum length
  is unresolved.
- Product result cardinality: `0`, `1`, and `2+`; maximum result count and
  pagination are unresolved.
- Own order-history cardinality: `0`, `1`, and `2+`; maximum order count and
  pagination are unresolved.
- Loading/error, authentication, and ownership are categorical/security states,
  not numeric BVA boundaries.

## Step C - Test case engineering

Eleven FR-20 test cases are designed in
`Submission/reports/test-case-report.md`, using labels verified in
`frontend-mobile/App.js`:

- `TC-FR20-MOB-001` through `TC-FR20-MOB-005`: empty, one-character,
  zero-result, one-result, and multiple-result product browsing.
- `TC-FR20-MOB-006` and `TC-FR20-MOB-007`: loading and failed product-request
  states.
- `TC-FR20-MOB-008` through `TC-FR20-MOB-010`: zero, one, and multiple own
  orders with required fields and translated status labels.
- `TC-FR20-MOB-011`: ownership isolation between two authenticated users.

The student supplied two controlled script runs on 2026-10-20:

- With User ID 2 configured with exactly 1 order:
  `TC-FR20-MOB-009` returned `PASS`; `TC-FR20-MOB-010` returned `INFO`.
- With User ID 2 configured with 2 orders:
  `TC-FR20-MOB-010` returned `PASS`; `TC-FR20-MOB-008` and
  `TC-FR20-MOB-009` correctly returned `INFO` for their zero/one-order
  partitions.

Together with the earlier zero-order run for `TC-FR20-MOB-008`, this provides
API-only evidence for nine cases. They are recorded as `API Passed; UI
pending`, not as complete mobile UI passes. Cases 006 and 007 were then manually executed and passed from the supplied
UI evidence: `Đang tải...` was displayed for the delayed request and
`Failed to fetch` was displayed for the failed request.
