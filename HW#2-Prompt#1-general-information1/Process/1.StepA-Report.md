## Evidence collected

### FR-05 - Product listing and search

- Web surface: `frontend-web/src/pages/Home.jsx`.
- Mobile surface: `frontend-mobile/App.js`.
- Backend endpoint: `GET /api/products?search=...` in `backend/server.js`.
- An empty search value causes the backend to return all products.
- A non-empty search value is interpolated into a `LIKE` query and the
  response is rendered as a product array when successful.
- The web UI has a product-list heading, search input, search submit button,
  product cards, and a result-count display when the result array is
  non-empty.
- The mobile UI has product loading state, an error state, a product list, a
  search input/action, and a result-count display when the result array is
  non-empty.
- The source does not establish a documented maximum search length or a
  separate no-results message. These are unresolved specification points, not
  assumptions.

### FR-11 - User order history

- Backend endpoint: authenticated `GET /api/orders/my-orders`.
- The endpoint filters orders using the authenticated token subject
  (`req.user.id`) and sorts by descending order ID.
- Backend detail endpoint: `GET /api/orders/:id` exists but is not protected
  by the authentication middleware and returns an order by ID.
- Mobile source stores the authenticated user's orders and fetches them after
  login through the `my-orders` endpoint.
- The mobile order-history rendering and exact status/date/total labels still
  require a focused source read before classes are finalized.
- The inventory says the user should see order ID, date, total, and translated
  current status; the implementation evidence for each displayed field must
  be checked before writing expected results.

### FR-19 - Admin user management

- Admin UI surface: `frontend-admin/src/App.jsx`.
- Backend endpoints: authenticated `GET /api/admin/users` and
  `DELETE /api/admin/users/:id`.
- The list query selects ID, name, email, role, login-attempt data,
  lock-expiry data, and shipping address; it does not select the password.
- The admin UI currently renders ID, email, role, phone, and a delete action.
  The backend list query does not select `phone`, so the displayed phone
  value must be treated as an implementation question, not an expected
  requirement.
- The backend delete handler does not show a current-admin exclusion check in
  the inspected code. Whether deletion is prevented elsewhere must be checked
  before defining an expected result.
- The backend handler does not show an explicit admin-role authorization check
  on these two endpoints; authorization behavior must be verified from the
  full authentication/role implementation before partitioning.
- The admin UI checks `res.data.user.role` after login before storing the admin
  token, but the inspected backend admin endpoints only use
  `authenticateToken`. A non-admin token behavior therefore requires runtime
  verification and must not be assumed from the UI check.

### FR-20 subsection - Mobile product browsing and order history

- Mobile surface: `frontend-mobile/App.js`.
- Product browsing reuses the mobile product fetch/search/list/detail flow.
- Product loading, error, empty-array behavior, and result-count behavior are
  represented by separate state or rendering branches.
- Mobile order history reuses the authenticated `my-orders` request and local
  `orders` state.
- Mobile source evidence for the exact order-history screen, empty state,
- The mobile order-history screen is rendered inside the authenticated profile
  view. It displays order ID, localized date, formatted total, and a mapped
  Vietnamese status for the five observed statuses: pending, confirmed,
  shipping, delivered, and canceled.
- The mobile empty-order state displays `Bạn chưa có đơn hàng nào.`.
- The mobile UI exposes cancellation for pending and confirmed orders. This
  cancellation behavior is outside the selected FR-20 subsection and will not
  be partitioned here.
- The inspected mobile source does not show a separate order-detail route or
  an order-history back-navigation control.
- No classes are inferred from the out-of-scope mobile authentication,
  profile, cart, checkout, or cancellation code.
